# Specialist files and secure manual handoff

**Decision:** selected-file or frozen engagement-selected packet, required secure manual route; optional portal. R-D02-04 / RW08/RW13 / M36. This is a product/security contract grounded in ISA 620.11(d), A29–A31, applicable confidentiality and OWASP authorization guidance. The audit standards do not prescribe token format or endpoint design.

## Grant record and operation

`grant_id, revision, firm_id, engagement_id, contribution_id, recipient_person_id, recipient_organization, purpose, scope_kind, manifest[], permissions[], issued_by, issued_at, not_before, expires_at, revoked_at/reason, agreement_ref/version, disclosure_authority_ref/assessment, channel, receipt_refs[]`.

Each manifest row identifies exact evidence ID, version, content hash, allowed view/download, name safe for recipient, and any redaction derivative with original provenance. Scope_kind is selected-files or engagement-selected-set. Both resolve to an explicit frozen manifest. No wildcard for all firm files, automatic future uploads, unrelated clients, hidden attachments, staff HR records or source credentials. A replaced file or newly selected evidence requires a new manifest version and recipient approval/issue. The original remains historical; an unsafe/superseded share can be revoked immediately.

Senior with share authority can issue a valid bounded packet; ordinary packets do not require unnecessary second administrative approval. The disclosing authority/confidentiality decision must exist and any required policy review must have been performed. The recipient cannot grant themselves more scope. A specialist is not added as preparer, reviewer or partner merely to permit file access. The same person working on two clients has separate contribution and grant records.

Portal preconditions on **every** list, metadata, preview, thumbnail, original download, range request, export and return-upload request: authenticated intended recipient, active account, actual current grant revision, current time within half-open validity interval, correct firm/engagement/contribution/object/version, permitted action, no revocation and valid purpose state. Enforce server side, deny by default; guessed object IDs and direct URLs do not bypass checks. Do not put unrevocable public object-store links in exports. Streaming authorization is checked at request start; revoke ends active sessions/streams where supported and denies subsequent requests/ranges. Already delivered bytes cannot be recalled.

Read/download are separate rights. Browser viewing transmits content and cannot guarantee prevention of screenshots or saving; a view-only label is not digital rights management. Revocation/expiry blocks future server access and future shares, not copies already downloaded. Record contractual return/deletion request and actual acknowledgment separately; never claim remote deletion occurred. Internal audit-retention obligations remain with the audit firm; external deletion does not erase the retained audit evidence.

Returns create new specialist-return artifacts linked to contribution, grant/packet version and sender/recorder. Do not overwrite source evidence. Return quarantined/unaccepted until the existing evidence checks and auditor evaluation are complete. If grant expired, use a newly authorized return-only route or internal manual receipt; do not reactivate historic outbound access just to receive a report. Any portal scanning/provider/storage control is the existing owning security infrastructure, not a claim that D02 has deployed it.

## Required manual route when portal is deferred

1. Senior selects and freezes permitted exact files; export only authorized/redacted copies and a manifest with packet version and hashes. Review recipient identity, purpose, agreement and disclosure assessment.
2. Use an approved recipient-restricted transfer service or encrypted packet. Deliver any decryption secret through a separate authenticated channel; record channel and recipient confirmation. No automatic email/message is sent by this research task. If the firm has no approved secure transfer channel, retain the prepared packet and prevent dispatch until its actual owner selects one; no insecure fallback is presented as compliant.
3. Record prepared → authorized → dispatched → received, sender, recipient, actual dispatch/receipt evidence and dates; failed/unknown delivery must be reconciled before retry. Manual dispatch records no automatic provider receipt. A service's enforceable link expiry/revocation is distinguished from the intended expiry recorded in Audit Core.
4. Receive the original opinion/evidence through the approved channel. Authorized auditor records who actually sent it, when/how received, exact packet basis, original and provenance, and performs evidence/adequacy evaluation. Manual recording is not the expert logging in or signing digitally.
5. At closure or changed scope, revoke provider access where supported, stop further sends, record deletion/return requests and acknowledgments, retain the firm's audit record and all prior manifest versions. A downloaded encrypted packet cannot be made inaccessible after its recipient knows the key; confidentiality obligations address retained copies.

This route is a complete v1 product workflow, not an unresolved portal decision. The optional portal is a separate implementation option with the same security and return contract. Runtime denied-access/provider behavior must be verified when the selected path is implemented; paper specifications never count as a passed security test.
