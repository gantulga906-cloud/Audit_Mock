# Method specification — [Mxx / original AUTO/variant/procedure IDs]

| Field | Required content |
| --- | --- |
| Identity | Method/version, original source/method IDs and owning domain/record/command |
| Authority | Full applicable standard paragraphs/articles, policy owner, edition, effective/adoption evidence |
| Classification | Binding requirement, permitted policy election, numerical convention or professional judgment |
| Applicability | Entity/framework/sector/jurisdiction/period, prerequisite/trigger and explicit exclusions |
| Input schema | Row/unit grain, required/optional/conditional fields, data types, null/zero, currencies/scales, sign and dates |
| Algorithm | Approved equations/pseudocode or decision table, parameters, derivation/primary methodology source and alternative rejected |
| Precision | Decimal representation, rates/day count, round stage/mode, tolerance and numerical solver conditions |
| Outputs | Typed result, supporting movements/components, assumptions, exception/unsupported codes and human decision |
| Integrity | Reconciliation, allocation/nonduplication, source row lineage and allowed changes |
| Independent examples | Input vectors, separately derived expected values/decisions, uncertainty/tolerance, checker and computation/source identity |
| Scenarios | Normal/boundary/adverse/missing/unsupported/denied/change/retry/history and relevant cross-method effects |
| Governance | Author, independent numerical reviewer, professional approver, implementation/QA/practitioner acceptance evidence |
| Version impact | Source/mapping/parameter/method stamps, stale-result rules, backward compatibility and historical preservation |

A completed template is not approval until the actual authority/checker decisions are recorded. Synthetic example rates/percentages never become current law or firm defaults.
