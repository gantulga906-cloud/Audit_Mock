## 2. Working method for every batch

1. Read the exact source rows, current implementation and existing tests for the selected contract. Reopen original cells/pages/diagrams where interpretation matters.
2. State the concrete delta: working behavior to preserve, missing behavior to implement, missing technical evidence, missing source decision or missing external adapter.
3. Extend the owning shared records and commands. Keep IDs, provenance, revisions, original bytes, authorization and history intact. Avoid duplicate browser-only business state.
4. Exercise a connected persisted engagement across actual roles. Capture normal progression, meaningful return/failure, unauthorized action, changed input and recovery/retry as relevant.
5. Check independent expected values for calculations and source-specific branches. A table or automation card with a result is not enough.
6. Update technical evidence and task status without manufacturing independent acceptance. Record current code/build, scenario/test hashes, actual outcomes, retained limitations and the next ready batch.

Use package prerequisites at the needed capability level. A bounded A26/A27 path can use the already working completion/review foundations before all earlier variants close. Missing prerequisites discovered in that path belong to the same connected batch. Final core release still requires every applicable obligation.

Do not turn every workflow into a “Next” wizard. Handoffs follow authoritative records and approved decisions. Saving, replying, reviewing, authorizing, issuing, receiving and locking stay distinct.
