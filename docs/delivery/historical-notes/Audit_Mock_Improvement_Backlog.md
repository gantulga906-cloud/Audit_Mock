# Audit Mock improvement backlog

Based on the 9 November 2026 audit of v2 (`39ae9e6`). This is a work plan for the next prototype and subsequent pilot. Owners below are suggested responsibilities, not assignments. “Done” means the stated scenario passes at the stated depth.

**Next release target:** One fictional engagement, one fixed-asset-additions workstream, and the same records carried from enquiry and acceptance through assignment, evidence, sample testing, review, finding, reporting and custody. Include a scenario where formal quality review applies and one where it does not, using firm-approved demo rules. Reuse the existing form catalogue, Gantt, calendar, review loop and prototype stack.

## Research outputs to ask for

- **Decision table:** source locator, rule, action it governs, required record/version, who can decide, exception/N/A and invalidation behavior. Start with A1–A3.
- **Observed role journeys:** capture four tasks using the same fictional engagement: assistant clears a return, senior resolves a schedule conflict, partner finds a blocked release, quality reviewer locates their assigned scope. Record current pain and the proposed change.
- **Focused product comparisons:** use the existing audit-product study as a starting point. Compare two competing audit workflows for review and evidence, and two adjacent scheduling/practice tools for capacity and rescheduling. Capture trigger, next actor, state change and evidence. Reuse the mechanism if it fits.
- **Verification ledger:** scenario ID, source criterion, fixture, steps, expected and observed outcomes, owner, remaining gap. Keep prototype verification separate from production controls.
- **Automation and configuration cost register:** inputs, frequency, exception cost, operator, reviewer, reusable support, maintenance burden and who pays for a requested change.

Sequence: **A1–A3 rules → A4–A5 connected journey with B1–B4 → B5 evidence and walkthrough → C1–C4 targeted expansion → C5 pilot readiness.** The first release does not need to execute all 70 forms, automate all 58 methods or turn every BPMN node into a screen.
