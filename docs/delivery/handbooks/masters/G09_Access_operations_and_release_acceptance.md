## Identity, access and current limits

## Workspace and UX compatibility

The current workspace places role queues and engagement context around full-page workpapers, contextual evidence, separate independent desks and purposeful next actions. 'One window' means preserving the relevant case/context and source record while moving among tasks; it is not one giant form or a compulsory Next wizard. Compact forms should preserve legibility, actual controls and pending work. A dedicated next action can help only when the transition and preconditions are truthful.

Prior audit-product/enterprise UX research informs these decisions but was not freshly repeated as a broad study. Refactoring UI and Designing Interfaces were inspiration references, not books claimed read in full. Source audit-products/audit-patterns/external-patterns/design-spec remain historical rationale, with later functional state checked against code. Navigation/queue recovery fixes are recorded locally; current functionality must stay reachable as more methods are added.

E2E-09-NEGATIVE revokes access and attempts direct resource routes, stale/reused commands and self-approval. E2E-09-CHANGE migrates roles/storage/template/data without losing earlier identities/artifacts. E2E-09-EXTERNAL reconciles an unknown provider outcome before retry and retains actual attempts. E2E-09-LOAD uses approved representative workloads/targets, not undocumented synthetic assumptions. These are specifications; prior local evidence is retained separately.
