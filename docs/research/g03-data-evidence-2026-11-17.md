# G03: data, evidence, requests and confirmations

17 November 2026. Engineering implementation of the published 16 November G03 handbook, extending published G02 baseline `6d467ac2557018ced0c12324c48a03e7603813e0`.

## Result and compatibility

An accepted, planned engagement can now use independently approved import profiles, full-source reconciliation and controlled data methods; assess actual evidence for a specific purpose; preserve original files through replacement; and record independently reviewed confirmation conclusions. Import, receipt, acceptance, usable data, intended-use coverage and professional sufficiency remain distinct.

New standard extended conversions enable G03 alongside G01/G02. Earlier engagements retain their existing behavior until the partner explicitly enables G03 from Data. Enabling it does not erase earlier work or grant approvals. Earlier issued requests without a documented intended-use scope show as unassessed until their actual requirements and received-file metadata are reviewed. Existing normalized CSV, A11, sampling, journals, fieldwork, review, reporting, EQR, custody and archive contracts remain.

The existing scoped model, SQLite transaction, command revision/idempotency and original-file store own these additions. There is no second database or automatic source migration. The preserved source registers, original 25 packages/128 tasks and independent acceptance decisions are unchanged.

## Working order

1. Complete current G01 acceptance and exact agreed terms, activate the engagement, and retain current named assignments and G02 planning. Existing programme ownership still governs requests; data preparation and independent data approval remain separate capacities.
2. In **Data → Import profiles**, declare the actual source columns, signed amount or debit/credit, source unit, sign and exact ISO or DMY date format. A different assigned reviewer approves the exact profile. Missing mandatory mappings are rejected. No ambiguous-date guessing, fuzzy identity matching or hidden currency conversion is introduced. A profile amendment creates a new revision and makes earlier reliance noncurrent until reassessed/reimported.
3. Receive the actual original CSV, retaining its content hash, raw record text, source cells/columns, row number and interpreted values. Invalid or ambiguous amounts/dates remain explicit. A genuine zero remains zero; a blank or malformed amount remains null. Corrected files create new original IDs and revisions. Earlier bytes and interpreted inputs remain retrievable.
4. Separately assess the original for its stated use. Record independent accepted control evidence, accepted-cohort count/total, the certified full-source row count, all supplied currency totals, one-destination account mappings, statement values, exclusions and actual investigation. A separate copy with identical content cannot supply an independent control. A missing source row cannot be hidden by a zero sum. Unknown amounts and unresolved quarantined rows prevent usable population approval. A separate reviewer approves the exact revision; downstream sampling/analytics use only current usable data.
5. Run the applicable controlled methods below against exact accepted originals. Each run retains its source IDs/versions/hashes, declared configuration, outputs, exceptions, explanations and review. Preparation, submission, return, explanation and approval events are retained within each version. A limited approval records a limitation and never supplies a usable-population prerequisite. Select the current applicable method versions when reconciling a population; source/disposition changes reopen their relying uses.
6. In **Evidence → Requests**, state each item's actual purpose, entity, period, evidence type, recipient/owner and agreed date. An unagreed date stays blank. Comparative/post-period requirements need a stated basis. Record manual issue separately from drafting. File receipt retains actual supplier, channel, date and declared scope. One file may be individually accepted for several matched items; other items stay outstanding. An accepted wrong-period file does not fulfil the request.
7. Previously received originals can be explicitly linked to an item. Proposed alternative evidence needs current matching entity/period, rationale and a separate independent approval. An expressly necessary positive confirmation reply cannot be replaced by automatic alternative approval. Scope corrections and replacements preserve earlier metadata, originals, approvals and use history. A completed request is reconsidered through the existing reopen path before withdrawal; cancellation does not erase its earlier work.
8. In **Audit registers → Evidence use**, record the exact original, requested item where applicable, actual procedure/field, assertion, purpose, inspection date, readable-content assessment, whole-file/page/cell/section anchor, relevance, reliability and conclusion. A supported use needs current accepted evidence. A negative/limited evaluation can retain the actual received or rejected original; rejection is not rewritten into acceptance. Contradictory/more-work/limited positions retain their next assigned owner and follow-up. A tickmark/discussion remains separate from this conclusion and from independent workpaper review. Replacing one of two uses of a shared original stales that use without invalidating the other supported use.
9. In **Confirmation records**, retain the actual subject/date/amount/currency, responding party/address basis, auditor-controlled reply route, actual manual dispatch reference/evidence and delivery result. A local response link requires the independently reviewed prepared case and exact request scope. Its recipient explicitly declares the response scope; receipt is not acceptance. The local link is single-use, expires, is revoked on reissue, and loses eligibility when its issuer/scope/case is no longer valid. It proves neither external message delivery nor bank identity.
10. Independently evaluate actual replies, amount/currency comparisons, differences, nonresponse, management-forwarded reliability and management refusal. Required positive replies, unsupported negative-only conditions, unknown dispatch outcomes and unresolved differences cannot produce an unsupported favorable conclusion. Refusal records preserve actual reasons, risk/governance/reporting implications and the next owner. Significant evidence/confirmation limitations must reach the later evidence-sufficiency evaluation; G03 does not choose the audit opinion.

## Controlled method contracts

| Source method | Implemented bounded behavior |
| --- | --- |
| AUTO-001 | Per-item entity/period/type/purpose coverage: covered, missing, rejected-only, independently approved alternative or unassessed. Draft/cancelled requirements do not count. Partial date intervals are not automatically unioned. |
| AUTO-002 | Approved column/unit/sign/date interpretation, actual entity/date/currency checks and retained row-specific defects. UTF-8 CSV is the structured importer; other originals remain received files. |
| AUTO-003 | Certified count/amount bridge over retained source rows, disjoint dispositions, declared business keys and exact original-record duplicate groups. Failed/empty imports and unexplained controls cannot appear clean. |
| AUTO-004 | Exact master-family matching with optional actual validity intervals; historical inactive rows can be valid, overlapping/unmatched identities remain exceptions. No fuzzy or external-registry resolution. |
| AUTO-005 | Declared account/account-detail TB grain, opening + debit − credit to closing, separate detailed-ledger debit/credit reconciliation and whole-ledger balance only for a declared complete ledger. Selected-account extracts do not claim whole-ledger completeness. |
| AUTO-006 | Exactly one signed primary statement destination per in-scope account, explicit statement period/currency/display scale and residuals. Duplicate/unmapped destinations remain exceptions; split allocation is outside this minimum. |
| AUTO-007 | Controlled statement nodes, declared signed totals, exact note references and repeated-value links with explicit units/tolerance. Cyclic/missing references and empty checks are rejected or retained as exceptions. No semantic disclosure-completeness opinion. |
| AUTO-008 | Exact prior-closing/current-opening periods, authoritative-prior basis, common accounts or a one-to-one crosswalk and linked independently approved opening adjustments. Unmatched accounts and residuals remain explicit; arithmetic does not complete the G02 opening-balance evidence assessment. |
| AUTO-010 | Declared comparable periods/units, absolute and percentage predicates and explicit ratio expectations. Zero/missing denominators remain not evaluable. Flagged relationships need actual explanation/evidence; refresh retains old reviewed explanations and opens new cases. No generated expectations or forecast. |

Method inputs use the source schemas shown beside each calculation form. Monetary calculations retain integer cents with safe numeric bounds; display amounts are shown in major units with explicit statement scaling. Files are limited to the existing 5 MB receipt boundary; structured CSV processing is limited to 750 KB and 3,000 data rows. The method-configuration profile permits at most 200 declared relationships per configuration list. Unsupported schemas/complex transformations need an explicitly versioned extension rather than silent interpretation.

## Source changes, scope and original integrity

Profile, source, row-disposition, opening-adjustment approval and linked method changes are checked against their exact relied-upon versions. Metadata correction records its earlier scope/status and reopens affected accepted parts and submitted/reviewed work. Unrelated materiality and unrelated methods remain current. Original download checks the stored content hash and uses an attachment response with type-sniffing disabled. Binary receipt checks declared file signatures; opaque DOCX/XLSX/PDF receipt is not an automatic parser, malware scan or authenticity guarantee.

Request originals, negative evaluations, earlier request uses and all data-method source versions join the retained authorization evidence inventory. Whole-engagement membership and assigned roles apply to original access, preparation, review and local response eligibility. This bounded profile does not introduce a client/specialist portal or pretend that engagement-wide access is a fine-grained confidential-document permission system. Restricted portal/document grants and approved external delivery/ERP adapters remain explicit integration work under their owning later guides; no external messages are sent by this checkpoint.

## Verification and remaining authority

The checkpoint contains full regression/build/foundation results, actual browser checks, exact expected/actual observations, all 30 G03 criteria with evidence class, source workflow links, preserved-backlog comparison and publication byte hashes. Tests exercise standard G01/G02 context, malformed/ambiguous rows, same-file controls, master ambiguity, ledger imbalance, casts/references, opening support, undefined ratios, wrong-period evidence, partial coverage, independent alternatives, selective replacement, local-link replay/reissue, required-positive limitations, management refusal, revoked access, exact retry and restart.

All 2,247 registered obligations, 70 forms, 22 variants, 58 minimum automations, 58 pending extensions, 20 dependencies and 1,012 BPMN rows remain. Direct fixture evidence is not an independent source-acceptance decision. Partial A14/A18 observations are not combined into a complete lifecycle. Firm-specific legal applicability and actual professional sufficiency remain human decisions. G04 has not started; main, the running local preview and its saved data are unchanged by publishing this development checkpoint.

The file-handling boundary was checked against the official [OWASP File Upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html). The confirmation distinctions were checked against [ISA 505 in the official IAASB Handbook](https://ifacweb.blob.core.windows.net/publicfiles/2025-09/IAASB-2025-Handbook-Volume-1.pdf), paragraphs 7–16: auditor control, response reliability, nonresponse/refusal, necessary positive replies, negative-only conditions and actual evaluation remain distinct. These references inform the implementation boundary; they do not establish local adoption or whole-standard compliance.
