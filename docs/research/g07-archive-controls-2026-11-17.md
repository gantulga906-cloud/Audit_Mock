# G07: final file, custody, retention and later facts

17 November 2026. Implementation guide for the explicitly selected G07 core profile. Read with the original G07 handbook, PILOT and the current checkpoint. Source requirements and acceptance remain intact.

## Select and administer the profile

Complete G06 reporting preparation first. The engagement partner selects the separate file-control profile on the Archive page with an actual reason. Existing work is retained; the selection does not backfill approvals or change legacy engagements automatically.

Upload archive administration sources through the dedicated archive source control. Another authorized actor assesses the exact original before it supports a decision. These originals remain separate from audit evidence, including when the audit file is sealed. They cannot silently become ordinary audit reliance.

M12-F02/F04/F07/F08/F09/F10/F11 decisions identify an actual named partner, a current approved appointment, the specific file/disclosure/retention/recovery/disposition capacity, an accepted original authority source and its application. Report-signing authority alone does not substitute for these decisions. Submitted decisions pin exact source versions; changed sources invalidate reliance rather than silently repinning.

## Assemble and seal

Review the exact signed and issued report, statement/notes originals, work versions, cross-references and outstanding review matters. Assembly diagnostics distinguish missing, corrupt, unavailable and stale items. A clean diagnostic is informational; a separately approved assembly record and existing release/distribution controls are still required to seal.

Choose the actual applicable assembly anchor and deadline from a reviewed policy. No universal assembly period or retention minimum is installed. Administrative successors preserve earlier content, hashes and history; they describe the narrow index change and confirm that it adds no audit conclusion. New audit work uses the substantive amendment route and its real dates.

## Independent custody and continuing health

The partner identifies the actual independent custodian, appointment source, independence, location, medium and confidentiality conditions. The separately signed-in custodian downloads the exact offered package and inspects every report/original item using an appropriate reader. Downloading bytes or matching a hash alone does not establish readability.

Each inspection records actual day, location, medium, receipt, restrictions, per-item method, result and observation. Unknown, unavailable and unreadable results remain unresolved. Every item must be recorded as actually readable before acceptance. Repeating the same inspection identity has one effect; changing its payload under that identity is denied.

Return discrepancies with a responsible repair owner. A reoffer records the performed resolution and preserves earlier offers. Later inspections can record degraded health without erasing the original acknowledgment. Continuing holds, retention decisions and access restrictions survive transfer.

The reference fixture actually decodes its fictional UTF-8/JSON contents. PDF/Office readers, media migrations, independent storage adapters and production readability rehearsals remain separate work.

## Retrieval and disclosure

Approve the named requester, disclosure authority, confidential scope and expiry in M12-F07/F10. A report-only recipient sees one permitted item. Subset views omit unrelated original names, whole-file counts, full manifest digest and hold metadata. Downloads enforce the same scope; expiry, revocation, changed authority and membership removal deny continued access. An administrative successor needs its own grant.

Stable object identifiers support the authorized reference listing. Broader inspector dispatch, receipt and return instruments still require their own workflow and source acceptance; a grant or download is not a delivery acknowledgment.

## Retention, holds and bounded disposition

Record the actual jurisdiction/scope, policy edition, original source, anchor and why it applies, minimum and selected period, and restrictions. Unresolved requirements retain the file and block disposal. A confirmed reviewed successor can resolve a named unresolved determination; it cannot shorten an inherited longer deadline. All applicable ancestor policies and every remaining hold continue to apply. Releasing one hold does not release another.

Eligibility, independent authorization and performed removal remain distinct. The existing synthetic-only safeguard is retained. The supported test operation removes only the local synthetic archive payload and records the residual originals/backups and next work. It expressly records that secure erasure was not proved. Real files and disposal across copies, backups or storage services require a separately designed production adapter, actual residual reconciliation and appropriate authority. Expiry never triggers automatic destruction.

## Actual backup and isolated recovery

Run `node scripts/pilot-recovery.mjs SOURCE.sqlite NEW-TARGET-DIRECTORY` against an authorized source and a new private directory. The utility refuses to overwrite an existing target. It uses the supported SQLite backup API to create a snapshot and restores that snapshot into a second database. Integrity checks and manifests compare actual originals, retained reports, archive hashes, identifiers, memberships and access scopes. The connected test starts the restored application and verifies scoped retrieval and denied access.

The verification receipt can be uploaded as an archive administration original and independently approved in M12-F09. Keep the database copies, credentials and sessions private. This local rehearsal does not establish operational RPO/RTO, independent storage resilience or document-format readability. Never publish the runtime databases or run a write experiment against the preview.

## Later facts across all three phases

An actual discovery timestamp and source attach to the exact original report and chronology. The supported phases are dated but unissued, issued but unsealed, and sealed. No fake issue/archive is created for an earlier phase. Management and governance discussion outcomes precede the partner's response decision.

- Before issue: an approved full-redating response reopens the exact original reviewed work. Actual changed work and independent review precede renewed completion, opinion, sections, preparation and report authority.
- Issued but unsealed: the same controls produce a separate new issue while retaining the earlier report and recipients.
- Sealed: a separately approved substantive M12-F04 amendment links the response to the original protected file. Its successor preserves the earlier archive.

For every rework phase, an old signature cannot authorize the new report. Actual authorization, signature, issue, original-package receipt, reviewed final assembly and independent readable custody precede response closure. No-change responses and prevention of reliance retain their own rationale and communication outcomes; failed notices cannot masquerade as completed delivery.

**Dual dating remains unsupported and open**, including the specialized limited-procedure path in R21.4. The interface makes this explicit and the server denies an unsupported selection. Full redating is the supported route; this does not remove the original requirement.

## External references and unresolved adoption

The [SQLite Online Backup documentation](https://www.sqlite.org/backup.html) supports the snapshot/restore approach. It does not establish business recovery targets or media readability.

The [IAASB 2025 Handbook, Volume 1](https://ifacweb.blob.core.windows.net/publicfiles/2025-09/IAASB-2025-Handbook-Volume-1.pdf), ISA 230 paragraphs 14–16 and A21–A24, informs the separation of administrative assembly, later audit work and retained change history. Application and local adoption require an actual responsible decision.

The [Mongolian legal source](https://legalinfo.mn/mn/detail?lawId=11192) returned HTTP 403 during this review. No current consolidated local retention rule was certified from it. No assumed five- or ten-year legal default is embedded.
