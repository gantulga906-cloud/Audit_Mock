# G06: opinion, reviewed wording and controlled issue

17 November 2026. Implementation guide for the G06 core checkpoint. Follow the original G06 handbook, G05 completion and PILOT for the preserved source requirements. This guide describes the new controlled profile and its bounded engineering evidence.

## Working order

1. Complete actual G05 work, the current final evaluation, source documents and required reviews. An authorized partner explicitly enables the G06 profile before issue. Historical engagements retain their existing path; enabling does not silently adopt old opinion/preparation approvals.
2. Prepare M10-F09 with separate human judgments for evidence adequacy, known effects, possible evidence-limitation effects, materiality and pervasiveness. Retain contrary information and actual supporting evidence. A material known-effect judgment links a real current uncorrected finding or qualitative effect from the final evaluation. An inability to obtain evidence is distinct from no known misstatement. The responsible auditor chooses the opinion; software rejects unsupported or contradictory recorded combinations.
3. Prepare one M10-F11 decision for each of KAM, going concern, emphasis, other matter, other information and additional regulatory reporting. Explicitly include or omit each with its actual reason and source. Included sections need their exact wording. Routine KAM/other-information inclusion with a disclaimer is restricted unless an actual special legal requirement is recorded. An emphasis section cannot cure an incompatible opinion decision.
4. Prepare M10-F10 with the actual framework/jurisdiction/edition, selected report form, approved title, opinion and basis wording, management and auditor responsibilities, date, addressee, actual issuer/appointment evidence, reporting duties and permitted recipients. Select actual contact records using the form's checkboxes. The source adverse-template conflict remains explicit: copied source wording does not choose the opinion or become approved text automatically. An actual reviewer resolves the wording issue and approves the exact report instance.
5. Return, revise and resubmit wording through the existing controlled register. Prior wording, the reviewer reason, authorship and exact versions remain recoverable. Independent preparation approval is distinct from the renewed report-work review and final authorization.
6. Review the current completion/report work and all applicable independent quality work. An unresolved formal EQR requirement or eligibility concern blocks release; report authority cannot waive it. Existing quality completion-date controls remain in force. Every supported new opinion still requires its actual professional decision and jurisdictional adoption.
7. Inspect the exact prepared report and full statement/notes pair. Authorization stores the actual rendered artifact and reviewed template-instance snapshot. The report identifies original statement, notes and management-authorization hashes. Sign those exact HTML bytes using the existing local Ed25519 route, then separately record the actual issue/reference. The actual local issue date must match the reviewed intended date for this profile. Earlier signatures cannot authorize changed wording or originals.
8. Create recipient attempts only for the exact approved, currently valid recipient scope. A local link is pending; it is not an external dispatch or receipt. Reconcile an unknown effect before retry. Retain confirmed failure and justified withdrawal. A withdrawn attempt is not silently reinstated. Duplicate current attempts and changed-payload retry keys are rejected.
9. The local recipient downloads the exact report, complete financial-statement original and notes original. Receipt requires all three actual downloads, the report/package hashes and an actual acknowledgment. Identical receipt retry returns the recorded outcome; a changed payload fails. An approved recipient who has not been attempted remains outstanding, even if another recipient received their package.
10. Use the existing G07 assembly and custody path. The connected normal test independently approves assembly, seals the exact package and recovers it after restart. G06 does not change retention policy or legal delivery requirements. Substantive changes after issue require the controlled successor route rather than overwriting issued content.

## Currentness and compatibility

The profile extends existing M10-F09/F10/F11 records, authorization snapshots, signatures, issue records and recipient-delivery tables. It does not create a parallel release store. Exact original-byte checks run before release and recipient access. An opinion pins the final evaluation version and independent approval. Relevant date, statement, finding/evaluation, source, preparation or recipient changes invalidate dependent reliance while preserving old artifacts and signatures.

A report-date change reopens the four date-dependent G05 positions; it does not automatically reopen unrelated statement/disclosure/legal/going-concern records or materiality. A changed statement package reopens all eight affected final assessments. A changed canonical contact's address/capacity invalidates pending access to the old recipient scope. No new source requirement, automation or area method is removed by enabling the profile.

The actual report wording is a reviewed engagement-specific instance with source provenance. It is not a newly approved firm-wide methodology library. Existing source-form editing/adoption remains available under G08. Real identity-backed signing, external dispatch, regulator filing and legal effect remain adapter/adoption work under R22/G09.

## Verification boundary and retained work

Six dedicated persisted scenarios cover the decision guards, a connected accepted/planned/G05-completed engagement through exact issue/original receipt and archive handoff, the three modified-opinion paths, returned wording, corrupt originals/changed recipients, and changed dates/statements with unresolved required quality. The existing regressions retain earlier acceptance, planning, data, fieldwork, consultation, quality, report, custody and later-fact behavior. Separate observations are not combined into additional complete source lifecycles.

The supported opinion matrix covers five declared single-cause combinations: unmodified; qualified for a material nonpervasive known effect or evidence limitation; adverse for a pervasive known effect; and disclaimer for a pervasive evidence limitation. Combined material causes, rare interacting uncertainties and additional specialized professional alternatives remain unresolved with an explicit unsupported result, rather than being forced into a clean opinion. These requirements remain in the original backlog.

Full jurisdictional wording and disclosure/section acceptance, communication-specific recipient/confidentiality alternatives, required-EQR positive timing variants, complete A26 exception coverage, source-contract acceptance of AUTO-056/057 and regulated external adapters remain open. The scope/classification/wording checks do not supply semantic or legal approval. The original 25 packages, 128 tasks, 2,247 source obligations and all source inventories remain preserved. Independent source acceptance and production release remain separate.

G07 is the next implementation guide; this batch tests the existing archive handoff and does not claim new G07 breadth. Main, deployment and the running preview/database remain unchanged by development-branch publication.

## Official reference

The [IAASB 2025 Handbook, Volume 1](https://ifacweb.blob.core.windows.net/publicfiles/2025-09/IAASB-2025-Handbook-Volume-1.pdf), particularly ISA 700, 701, 705 and 706, informs the separation of human opinion judgment, report sections and actual dating. The selected edition, effective requirements and local adoption still require an actual authorized decision. No universal report prose is installed by this implementation.
