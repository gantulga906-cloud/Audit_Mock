# G08: source forms and controlled methodology

18 November 2026. Implements the G08 engineering workflows in the existing shared application. Read with the original G08/PILOT handbooks and this delivery's checkpoint. Independent source and whole-form professional acceptance remain separate accountable decisions.

## Working order

1. Open the firm's form library. The partner selects the controlled-methodology profile with an actual reason. Existing releases, pinned forms, answers and earlier approvals are retained. Legacy profiles continue using their existing contracts.
2. Record actual methodology/authority/workbook originals, their source and edition. Another authorized actor assesses the exact original bytes. A named current firm person receives a separate publishing grant backed by an accepted original. Ordinary partner/report authority alone does not supply this additional capacity.
3. Preview the actual workbook sheet and mapping. Select the source-form comparison or question-list columns. Check stable identities, types, repeated columns, applicability, clauses, merged ranges, formulas and validation rules. Resolve each unsupported/different source item explicitly before importing the exact preview as a draft.
4. Edit the draft, including fixed clauses and typed table columns. Record source edition, framework, sector, service, effective start/end and the actual date anchor. Select whether this release contains changes requiring affected engagements to assess their impact. A draft does not modify published content or engagement work.
5. Submit the exact draft. The independently authorized publisher reviews the candidate hash, predecessor, actual differences, professional basis, performed examples and conclusion. Publication preserves release notes and the prior release. Retirement is a separate retained decision affecting new use.
6. On an engagement, read the change notice and inspect applicable approved editions. Publication never migrates existing answers. Required-impact changes need an attributable assessment or actual adoption; a required procedure cannot be silently deferred as optional. A supported unaffected/defer decision records its actual reason against exact old/new digests.
7. Compare adoption against current answers and evidence. A changed/lost answer, incompatible table cell or detached link requires current explicit acknowledgement. Programme-level acknowledgement already implemented in G02 uses the same migration path and remains in force.
8. Perform, save, submit, return/respond/clear and independently review the actual work. Repeated rows retain stable IDs through reordering. Typed table cells now expose appropriate choices, dates, narratives and accepted-original selectors. Unknown, N/A, false and exact zero retain distinct treatment.
9. If another contributor saved first, compare the current content with the retained local attempt. Deliberately choose the revised draft, record why, then save against the new revision. The earlier current version, preparation attribution and reconciliation reason remain. Changed work requires appropriate renewed review.
10. Select current or identifiable historical work versions, recipient and purpose for a readable export. Preview the exact manifest and available/missing/unavailable/corrupt originals, then download that exact selection. The HTML contains title/code, source edition and coordinates, actual typed answers/rows, clauses, evidence references, actor/version/review and limitations. Export completeness never signs off the audit.

## Source fidelity and workbook boundaries

The source reader examines original OOXML bytes on the server. ZIP entry counts/expanded sizes, relationships, XML declarations, cell identities and range sizes are bounded. Duplicate identities, unsafe XML and external relationships are rejected or explicitly unresolved. Macros and external workbook data are not executed/fetched. Source responsibility dropdowns remain metadata and cannot grant application access.

Previous-row numbering, including shared formulas and unary-plus expressions, is identified as presentation sequencing. Other formulas remain unimplemented source expressions until an accountable mapping/method decision. A cached value is not an implemented audit calculation. Arbitrary Excel calculation, macros and complete Excel visual-layout parity are not claimed.

The frozen 70-form catalogue remains unchanged. New runtime source contracts retain source fields/instructions/clauses, corrected narrative and identifier/signed-amount types, and categorical source results inside repeating rows. Existing pinned digests are not rewritten. All 70 contracts are exercised through typed-answer roundtrips; that demonstrates supported representation, not independent semantic approval.

The fresh read-only comparison records 70 forms, 1,238 runtime fields and 62 fixed clauses, including exact source and normalized application codes. It retains each registered workbook hash separately from the currently supplied binary. Stages 1–3 differ from their registered binaries; Stages 4–5 match. Current files contain 272 presentation formula cells and 987 validation definitions; the registered inventory's 1,820 definitions is preserved. Source-anchor differences and combined/merged labels remain inspectable for per-form professional reconciliation. No current binary silently replaces the registered source edition.

Run `npm run verify:methodology-sources -- READ-ONLY-SOURCE-DIRECTORY OUTPUT.json` to reproduce the actual per-form comparison. The command reads the five supplied workbooks and writes a separate authored comparison. It never edits or resaves the originals.

## Release and security contracts

- Authoring grants and publishing authority remain separate. Exact draft identity prevents stale saves and self publication is denied. Changed/corrupt authority prevents publication without making the source problem disappear from the review screen.
- A controlled release records its exact content hash, predecessor, scope/date anchor, changes, professional review and validation examples. An international publication is a reference; responsible local adoption is separately recorded in the basis.
- Retired, future-effective, expired and outside-scope editions are unavailable for new adoption. Prior pins and historical signed answers remain identifiable. Unassessed legacy releases remain explicitly distinguished when the profile is enabled.
- New release notices show affected content without assuming email. Optional changes and mandatory impact assessments have distinct decisions. Adoption preserves compatible strings/row IDs; incompatible values clear only after exact current acknowledgement.
- Preview/export scope is enforced on the server. Removed engagement membership denies search and export. Locked files continue through G07's scoped archive route. Unrelated metadata and original contents are not added to selected exports.
- Source originals, historical templates and signed answers remain retained across adoption, retirement, conflict resolution and restart. Production identity/operations requirements remain owned by G09.

## Validation and remaining acceptance

Eight dedicated persisted/pure-contract tests cover actual mapping/import, separate named publishing authority, effective scope/retirement, all-form typed roundtrips, current/historical readable exports, actual return/response/clear/review, controlled adoption, stale/concurrent saves, unsafe sources, exact zero/N/A and cross-scope evidence. Existing G00–G07 and programme-level tests remain part of the full regression suite. The browser verifier exercises the real controls and actual downloaded HTML against a disposable database.

The G08 checkpoint records every original P04/P15 criterion, actual executed observations and source freshness. Engineering implementation and verification do not close independent professional/whole-form source acceptance. Per-form semantic decisions, Stage 1–3 source-edition reconciliation, jurisdictional methodology adoption and the broader G09/G10/G11 method/variant/release obligations remain visible. No original requirement, package, task or automation is removed.

## External implementation references

The reader uses [fflate's ZIP filtering API](https://github.com/101arrowz/fflate/blob/master/README.md) with explicit entry/size limits and [fast-xml-parser's documented parser](https://github.com/NaturalIntelligence/fast-xml-parser/blob/master/README.md) with unsafe document declarations rejected. These libraries parse source structures; their successful use does not establish workbook business parity or methodology acceptance.
