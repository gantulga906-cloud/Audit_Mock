## Wave 5 release verification

`npm run verify:release -- --build` runs the tests and production build and writes `.audit-pilot/source-verification.json`. The report pins the Git revision, source hashes, test content hashes with normalized line endings, build, actors and execution outcomes. It lists each criterion, lifecycle step, feature, automation, form and variant.

A lifecycle fixture is complete when a single passing test records the source steps in order against the same persisted engagement, with matching expected and actual outcomes, versions and all defined branch checks. Step coverage across unrelated tests stays visible separately. The source inventory retains every lifecycle and step, while explicitly approved scope decisions determine the applicable release set.

The A25 reference fixture now exercises all nine source steps and seven branch checks from assigned review through authorization. A review note can be returned or cleared against an exact submitted work and response revision. The system retains the decision, reviewer, timestamp and rationale in the workpaper, quality package and sealed archive. Archive tests also verify that an administrative successor inherits the longer approved retention deadline and remains retrievable with the same digest from an online SQLite backup.

The A08 reference fixture runs all nine materiality steps and five branch checks on one engagement. Form 1.3 records the intended users, benchmark alternatives, comparative stability, unusual results and exact accepted support. It calculates the entered thresholds and optionally records a separate threshold per applicable fieldwork form. Sampling pins the reviewed scope and performance threshold. Completion compares the outstanding amount with the scoped threshold while retaining the auditor's qualitative judgment. Reduced thresholds and reopened source evidence stale the affected work. Earlier selections and reviews remain in history. The existing unstructured records remain readable.

The report includes the 20 confirmed form dependencies, the 58 proposed automation extensions, and the plan's 185 BPMN gateways and 827 flows across all five stages. BPMN rows retain the exact source ID and unresolved disposition pending action-by-action verification. The report tracks operational checks for fresh setup, cutover and rollback, recovery, workload and deployment separately.

A fixture pass leaves its source contract open for independent acceptance. Record an actual decision in `scripts/pilot-release-acceptance.json` with its `kind`, source `id`, `sourceSha256` from the reported row, `decision`, accountable `owner`, separate `reviewer`, approval `reference` and `reason`. An `accepted` decision lists positive and negative `checks`, each with the scenario's `file`, `test`, test file `sha256`, `actor`, `action`, `branch`, `expected` and `observed`. The verifier reopens a decision when source content, test bytes, result or role evidence changes. Eligible E2E rows, BPMN transitions and future automations can receive a separately approved scope decision. Each future automation stays scope-pending until a decision is recorded. The D03 and D24 feature dispositions remain source-defined. No independent release decisions have been recorded.
